# 直播间场景Skill V3.1 团队验收用例
以下为**真实运行需人工记录**的测试，提交规则不等于测试通过。

| ID | 触发操作 | 必须看到的结果 |
|---|---|---|
| T01 | 新项目无参考图 | 需求确认卡→品牌预检→主方案→等待确认，不直接生图 |
| T02 | 有参考图但未上传 | 明确等待本项目图片，不生图 |
| T03 | 上传两张参考图 | 逐图分工拆解、用户确认前不生图 |
| T04 | 全棉时代新项目 | 实际检查绿色/白色PNG及色卡是否可读，#00AC97与RGB准确展示；不能假装已加载 |
| T05 | 奈丝公主新项目 | 读取官方LOGO.png，无源图则提示缺失、留空Logo位 |
| T06 | 确认主方案 | 先提示词与负面词、A/B/C差异，再生成3张**独立3:4**图 |
| T07 | 每轮图生成后 | 一定有A/B/C/都不满意/历史版、可多选修改与自由反馈；无法按钮时编号文字替代 |
| T08 | 选第1轮B，要求棉花减30% | 明确锁“第1轮B原图”，不改门窗家具关系，仍3张仅改幅不同 |
| T09 | 已锁第2轮A，新增仅供光照参考图 | 不改变原图构图及原品牌，变化限光影 |
| T10 | 无法访问历史原图 | 如实要求用户补传，不能假称原图编辑 |
| T11 | 3:4母图制作9:16居中安全预览 | 9:16框中心保留75%宽度、左右各裁12.5%；Logo/主播/标题/贴片遮挡检查 |
| T12 | 生图工具只返1张或按钮不可用 | 报告数量不足，继续提供编号反馈选项，不自动下一轮 |
| T13 | 用户选择“都不满意” | 提出下一轮改方向而不是偷偷沿用锁定图 |
| T14 | 用户确认定稿 | 最终图、Logo源图合成提醒、色彩校验、裁切评估、版本ID和待办 |
| T15 | 同事新设备安装旧版 | 告知需安装/同步最新版且必须含assets/logos真实PNG |

判定：**T01—T15全通过** 才可宣称团队平台验收完成；如平台不支持图编辑/交互按钮，记录缺口，不伪称实现。每次发版分别测试ChatGPT与豆包工作，不用一个平台结果代替另一个。
